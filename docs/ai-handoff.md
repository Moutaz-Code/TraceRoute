Notes from AI to AI
Writing / Communication Style
The user strongly prefers:
neutral tone,
grounded phrasing,
low theatricality,
low “corporate presentation” energy,
fewer unnecessary headings,
concise but still structured responses.
Avoid:
“That’s excellent.”
“This is a powerful design.”
“What the player does NOT…”
excessive emphasis formatting,
overexplaining obvious implications,
sounding like a pitch deck.
The user prefers:
cohesive thought grouping,
practical design discussion,
implementation-aware reasoning,
collaborative iteration.
Project Reality Constraints
This is:
a 3-week university MVP,
team of 3,
Android Studio + Java + OpenGL ES 3.0,
no Unity.
Design discussions should remain:
realistically scoped,
implementation-aware,
content-budget-aware.
Avoid suggesting:
highly systemic deduction engines,
large branching structures,
massive environments,
complicated AI systems,
freeform detective simulation.
The current project identity is intentionally:
curated,
guided,
compact.
Important Established Design Decisions
The following are basically locked unless the user changes them:
One murder case MVP.
Compact apartment setting.
Living room murder scene.
Business partner is killer.
Blunt-force trauma.
Emotionally impulsive murder.
Technically aware but not genius killer.
Artificial continuation of victim activity is the main manipulation theme.
Timeline instability is core gameplay.
Investigation-thread progression system.
Soft-confirmation deduction (no explicit contradiction submission gameplay).
Semi-explicit thread structure.
Investigation-centric timeline.
Layered precision:
human evidence = approximate,
machine evidence = precise.
Guided but selective deduction.
Reconstruction sequences are atmospheric/supportive, not dominant gameplay.
No fail states/timers for MVP.
Quiet oppressive tone.
Tragic ending tone.
Important Design Philosophy
The strongest emerging theme is:
Human memory is uncertain.    Machines record precise events.    But machines can be manipulated.
The game should continue reinforcing that idea.
Another key philosophy:
the player should FEEL smart,
without requiring real cybersecurity expertise.
Cybersecurity knowledge should:
help,
never gate progress.
Important Scope Philosophy
The user consistently leans toward:
simplification where appropriate,
thematic depth over mechanical complexity,
curated interactions over simulation.
If uncertain between:
“systemic complexity”  vs
“focused authored experience,”
the correct direction is usually:
focused authored experience.

Important Narrative Notes
Victim:
flawed, rude, selfish,
cruel to staff,
involved in illegal dealings,
but not cartoonishly evil.
Killer:
understandable but condemnable,
emotionally unstable,
dependent on illegal money flow,
escalates from intimidation to murder,
manipulates evidence afterward.
Wife:
not killer,
secretly aware of illegal dealings,
suspicious for legitimate reasons,
should not feel like fake red-herring writing.
Security/staff:
genuine resentment + suspicious behavior,
not murderer.
Most Important Gameplay Identity
The game is NOT:
“guess the clue combination.”
The player:
notices contradictions mentally,
follows investigative threads,
resolves chronology uncertainty,
stabilizes the narrative gradually.
The systems:
support deduction,
rather than replacing it.
